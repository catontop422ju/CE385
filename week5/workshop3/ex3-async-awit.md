<!-- ส่วนที่ 1: reportSequential (การทำงานแบบทีละขั้นตอน) -->

ใช้ลูป for...of คู่กับ await เพื่อดึงข้อมูลทีละคน โดยรอคนแรกทำเสร็จ (300ms) ถึงจะเริ่มทำคนถัดไป

รวมเวลาที่ใช้ทั้งหมดจะอยู่ที่ประมาณ 900ms (300ms × 3)

<!-- ส่วนที่ 2: reportParallel (การทำงานแบบพร้อมกัน) -->

ใช้ ids.map() สั่งยิงคำขอพร้อมกัน 3 คน แล้วใช้ Promise.all รวบตึงรอรับผลลัพธ์ทีเดียว

เวลาที่ใช้จะเหลือเพียงประมาณ 300ms (เท่ากับเวลาของ 1 รอบ) จึงเร็วกว่าแบบแรกถึง 3 เท่า

<!-- ส่วนที่ 3: safeReport (การจัดการ Error) -->

try: ใส่โค้ดหลัก ถ้าดึงข้อมูลสำเร็จและตัดเกรดได้ จะแสดงผลปกติ

catch: ถ้าหา ID ไม่เจอ จะวิ่งมาจุดนี้เพื่อพิมพ์แจ้งเตือน ช่วยป้องกันไม่ให้โปรแกรมพัง (Crash)

finally: พิมพ์ข้อความจบการตรวจสอบเสมอ ไม่ว่าจะหาข้อมูลเจอหรือไม่

<!-- ส่วนที่ 4: คำตอบทฤษฎี -->

จับ Reject ด้วย try-catch: เพราะคำสั่ง await จะหยุดรอจน Promise ทำงานเสร็จ แล้วโยน (throw) ข้อผิดพลาดออกมาใส่ Call Stack ปัจจุบัน try-catch จึงดักจับได้ ต่างจาก Callback แบบเดิมที่ทำงานแยก Stack ไปแล้ว

หากลืมใส่ await หน้า Promise.all: ตัวแปรจะไม่ได้เก็บ Array ข้อมูลจริง แต่จะเก็บสถานะ Promise { <pending> } ไว้แทน ทำให้พอเอาตัวแปรไปวนลูปหรืออ่านค่าต่อ โปรแกรมจะทำงานผิดพลาดหรือขึ้น TypeError ทันที
